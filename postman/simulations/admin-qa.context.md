# admin-qa

Локальная симуляция для проверки панели без изменений рабочей базы. Источник контракта: `rag-service/schemas/admin.py`, `routers/admin.py` и `routers/ingest.py`; опубликованный mock другого владельца не использовался — fixture создан по доступному локальному коду.

## Purpose

Next.js работает как настоящий клиент API. `postman/mocks/rag-api/default.js` содержит синтетические документы, mutable конфигурацию, загрузку, удаление и переиндексацию. Неподдерживаемые пути возвращают 501. Реального парсинга файлов и вызовов LLM нет.

## Execution

1. Заполнить `.env.local`: ADMIN_LOGIN, ADMIN_PASSWORD и SESSION_SECRET.
2. В одном терминале: `npm run qa:api` (Postman CLI 1.75+).
3. В другом: `npm run dev:qa`.
4. Открыть http://127.0.0.1:3002 и войти своей локальной учётной записью.
5. API симуляции: http://127.0.0.1:4900/rag. Для машинного журнала добавить `--output ndjson` к команде `postman simulation run`.
6. Остановить оба процесса через Ctrl+C. По умолчанию обычный `npm run dev` продолжает использовать рабочий backend.

## Assumptions

- Мутации fixture меняют только состояние локального процесса; новый запуск начинает с синтетических данных. Воспроизведение не доказывает поведение реального индексатора или модели. (observed 2026-10-29)
- В `.sim.yaml` указан путь к `config.yaml`, не к папке: установленный CLI отклоняет directory path. (observed 2026-10-29)
- `dev:qa` переопределяет только адрес и синтетические сервисные токены; учётные данные панели берутся из `.env.local`. (observed 2026-10-29)
